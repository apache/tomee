= System Properties Listing
:index-group: Unrevised
:jbake-date: 2018-12-05
:jbake-type: page
:jbake-status: published

This page lists the properties that configure TomEE and its embedded OpenEJB container.
Most of them are system properties, but some are read from other places (application
properties, resource declarations, `logging.properties`, JAAS options, the TomEE Embedded
configuration or the Arquillian adapter configuration). Each section says where its
properties are set.

== Setting properties

System properties can be set in several ways:

* as JVM options, for example `-Dopenejb.jndiname.format=...` in `CATALINA_OPTS` or `JAVA_OPTS`;
* in `conf/system.properties` of the TomEE (or OpenEJB) base directory, which is read at startup;
* in `conf/<profile>.system.properties` (see `openejb.profile`) or `~/.openejb/system.properties`;
* as `<SystemProperty>` (`new://SystemProperty`) declarations in `tomee.xml`;
* for embedded containers, in the `Properties` passed to `InitialContext` or `EJBContainer.createEJBContainer()`.

Application properties go in `WEB-INF/application.properties` (web applications) or
`META-INF/application.properties` (EJB jars and EARs). Most of them also accept a global
default as a system property. Module properties go in `META-INF/module.properties`, and
bean properties in the `<properties>` of an `openejb-jar.xml` `<ejb-deployment>`.

Every `openejb.*` key read through the options API can also be written with the `tomee.`
prefix (`tomee.foo` is an alias of `openejb.foo`; the `openejb.` key wins when both are set).

Resources, containers and services can also be configured with properties, see
link:embedded-configuration.html[Embedded Configuration] and
link:properties-tool.html[Properties Tool].

== OpenEJB and TomEE system properties

The properties in this section are system properties. Unless noted otherwise, set them with `-D` or in `conf/system.properties`.

=== Configuration and bootstrap

[options="header",cols="2,1,1,3"]
|===
|Property |Type |Default |Description

|`+hsqldb.reconfig_logging+`
|bool
|`+false+` (set when absent)
|HSQLDB setting. When it is not set, OpenEJB sets it to `false` (also as a JVM system property) so HSQLDB leaves the container's logging alone.

|`+<id>=new://<ServiceType>?<params>+`
|service URI
|none
|Declares a service (Resource, Container, JndiProvider, Service, Deployments, SystemProperty and so on) from a property whose value starts with `new://`. Supported query parameters: `type`, `provider`, `class-name`, `constructor`, `constructor-types`, `factory-name`, `properties-provider`, `template`, `classpath` and `classpath-api`. Resources also accept `aliases`, `depends-on`, `post-construct` and `pre-destroy`; Deployments accepts `dir`, `jar` and `classpath`; SystemProperty accepts `name` and `value`. Any other parameter becomes a service property.

|`+openejb.additional.lib.folder+`
|path (relative to openejb.base)
|`+additionallib+`
|Folder under the base directory whose jars the embedder adds to the container classpath. Provisioning also uses it as its default destination.

|`+openejb.assembler+`
|class name
|`+org.apache.openejb.assembler.classic.Assembler+`
|Assembler implementation class instantiated at OpenEJB startup.

|`+openejb.base+`
|path
|value of `+openejb.home+`
|Server base directory. `RemoteServer` uses it to find the `conf` directory that holds the shutdown secret.

|`+openejb.conf.file+`
|path or URL
|none
|OpenEJB configuration file path. It is resolved as given, then relative to `openejb.base`, then to `openejb.home`, or used as a URL. Takes precedence over `openejb.configuration`. When neither is set, `conf/openejb.xml`, `conf/openejb.conf` and `conf/openejb.json` are searched.

|`+openejb.conf.schema.legacy+`
|bool
|auto-detected
|JVM system property selecting where service property files are expected: `true` means `+conf/<service>.properties+` (legacy), `false` means `+conf/conf.d/<service>.properties+`. Auto-detected as legacy when two or more of `ejbd`, `ejbds` and `admin.properties` exist directly in `conf/`.

|`+openejb.configuration+`
|path or URL
|none
|OpenEJB configuration file path, used when `openejb.conf.file` is not set. After the search, TomEE writes the path of the file it found back to this key.

|`+openejb.configuration.strict-tags+`
|bool
|`+false+`
|Makes parsing of an application's `META-INF/app-ctx.xml` fail when the root element is not `appcontext`, `app-context` or `application`. By default other root elements are ignored.

|`+openejb.configurator+`
|class name
|`+org.apache.openejb.config.ConfigurationFactory+`
|Implementation class used by the Assembler to build the OpenEJB configuration (`OpenEjbConfigurationFactory`).

|`+openejb.extract.configuration+`
|bool
|`+true+`
|Writes the default configuration files (for example `conf/openejb.xml`, `logging.properties`) to the base `conf` directory if they are missing.

|`+openejb.home+`
|path
|none
|OpenEJB/TomEE home directory. The JSR-88 `VmDeploymentManager` requires it, and `RemoteServer` uses it to find the server to start and stop.

|`+openejb.io.util.timeout+`
|int (ms)
|`+5000+`
|Connect timeout for URL connections opened by OpenEJB's IO helper, for example when downloading remote files. Read once, at class load.

|`+openejb.libs+`
|path
|`+<openejb.home>/lib+`
|Directory of OpenEJB libraries that the Embedder loads.

|`+openejb.nobanner+`
|bool
|`+true+`
|Activate or not the OpenEJB banner. The container prints its version banner only when this is `false`. The standalone server prints its startup and services banner unless the property is set at all.

|`+openejb.offline+`
|bool
|`+false+`
|Offline mode: when true, containers and resources that applications reference are not created automatically. It is only used as the default value of `tomee.autoconfig`.

|`+openejb.placeholder.delimiter+`
|string
|`+:-+`
|Separator between a key and its default value in `+${key:-default}+` placeholders resolved by OpenEJB. Read as a JVM system property at class load.

|`+openejb.profile+`
|string
|`+development+`
|Name of the configuration profile. At init, `+conf/<profile>.system.properties+` is read as well as `conf/system.properties` and `+~/.openejb/system.properties+`.

|`+openejb.provider.default+`
|string (provider namespace)
|`+org.apache.openejb+` (`+org.apache.openejb.embedded+` when embedded)
|Default service provider namespace used to look up service providers (`service-jar.xml`) when no provider is given explicitly.

|`+openejb.service-type-adjustement+`
|bool
|`+true+`
|When a declared service (for example a `<Resource>`) has no type, TomEE guesses the type from its properties (for example `JdbcDriver`/`JdbcUrl` with `JtaManaged`/`UserName`/`Password` means `javax.sql.DataSource`). Set it to `false` to stop this guessing. Note the spelling `adjustement`.

|`+<openejb.\|tomee.><property>+`
|string
|none
|During deployment, every system property that starts with `openejb.` or `tomee.` is also published without that prefix. As a result `openejb.foo` always takes precedence over `foo`.

|`+org.apache.activemq.broker.jmx.createConnector+`
|bool
|`+false+` (set when absent)
|ActiveMQ setting that controls whether the embedded broker creates its own JMX connector. When it is not set, OpenEJB sets it to `false`.

|`+org.apache.openejb.api.resource.PropertiesResourceProvider+`
|class name
|none
|Global `PropertiesResourceProvider` used for every service that does not declare its own `properties-provider`. The properties it returns are applied last and override the declared ones.

|`+org.apache.openejb.api.resource.Template+`
|class name
|none
|Global `Template` implementation used for every service that does not declare its own `template`. A template can change a service's configuration before the service is built.

|`+<serviceId>.<property>+`
|string
|none
|Overrides or adds a property of the service (Resource, Container, JndiProvider and so on) whose id is `<serviceId>`. The id is matched without regard to case. Examples: `+<ejb-name>.activation.<property>+`, `+<persistence unit name>.<property>+`, `+<resource id>.<property>+`.

|`+<SERVICETYPE>.<serviceId>.<property>+`
|string
|none
|Full form of the service property override, with the uppercase service type as a prefix (for example `RESOURCE.myDs.MaxActive`, `CONTAINER.myContainer.PoolSize`, `ENTERPRISEBEAN.<ejb-name>.activation.<property>`, `PERSISTENCEUNIT.<unit>.<property>`). The forms `+<serviceId>\|<property>+` and `+<SERVICETYPE>.<serviceId>\|<property>+` also work.

|`+tomee.<suffix>+`
|string (alias)
|none
|Any `+openejb.<suffix>+` key read through the options API (system, application, module and bean options) can also be given as `+tomee.<suffix>+`. If both are set, the `openejb.` key wins. Keys read with plain `System.getProperty()` do not get this alias.

|`+tomee.autoconfig+`
|bool
|`+true+` (`+false+` when `+openejb.offline=true+`)
|When true, missing containers and resources that applications reference (for example default DataSources) are created automatically. Set it to `false` to turn off auto-configuration.
|===

=== Deployment and scanning

[options="header",cols="2,1,1,3"]
|===

|bool

|none

|`+envprops.override+`
|bool
|`+false+`
|Lets entries in `META-INF/env-entries.properties` override env-entries that are already declared. By default only missing entries are added.

|`+<locationName>.moduleId+`
|string
|none

|`+openejb.additional.exclude+`

|none

|`+openejb.additional.include+`

|none

|`+openejb.altdd.prefix+`

|none

|`+openejb.autodeploy.interval+`

|`+2 seconds+`

|`+openejb.check.classloader+`

|`+false+`

|`+openejb.check.classloader.verbose+`
|bool
|`+false+`
|If true, prints the class intersections (the duplicated files) in each `openejb.check.classloader` report entry.

|`+openejb.connector.<moduleId>.aliases+`
|comma-separated ids
|none
|Deploys the same standalone resource adapter additional times, once under each alias.

|`+openejb.connector.<moduleId>.skip-default+`
|bool
|`+false+`
|Skips the default deployment of a standalone resource adapter (rar). Use it with `+openejb.connector.<moduleId>.aliases+` to deploy only the aliased copies.

|`+openejb.core.skip-war-in-loader+`
|bool
|`+true+`
|Removes the war archive itself from the webapp's scannable URLs, which avoids scanning executable wars that embed TomEE.

|`+openejb.debuggable-vm-hackery+`
|bool
|`+false+`
|Debugging aid that strips the deployment: removes message-driven beans, entity beans, CMR relationships and the references to them from EJB modules.

|`+openejb.default.deployment-module+`
|class name
|none
|Module type (for example `org.apache.openejb.config.WebModule`) used for archives whose type cannot be detected. Without it, such archives fail with `UnknownModuleTypeException`.

|`+openejb.deployer.jndiname+`
|string
|`+openejb/DeployerBusinessRemote+`
|JNDI name of the remote Deployer EJB that the JSR-88 `VmDeploymentManager` looks up.

|`+openejb.deployer.save-deployments+`
|bool
|`+false+`
|Applications deployed through the Deployer EJB are saved to the additional-deployments list so they are redeployed on restart. The same key in the `Properties` of a `Deployer.deploy()` call overrides it for that deployment.

|`+openejb.deployer.war+`
|new or old
|`+new+`
|How the Deployer EJB deploys WAR files. `old` deploys WARs through the legacy OpenEJB app path instead of the web-app deployer.

|`+openejb.deployments.classpath+`
|bool
|`+true+` (`+false+` for an embedded `EJBContainer`)
|Whether or not to deploy from the classpath: searches the classpath for EJB, client and other modules and deploys them automatically.

|`+openejb.deployments.classpath.ear+`
|bool
|`+true+`
|Deploy the classpath as an ear: all modules found on the classpath are deployed together as one application named `classpath.ear`. When false, each jar is deployed as its own application.

|`+openejb.deployments.classpath.exclude+`
|regex
|`+""+` (nothing)
|Regex to filter the scanned classpath: selects which classpath entries are excluded from deployment and annotation scanning.

|`+openejb.deployments.classpath.filter.descriptors+`
|bool
|`+false+`
|Also applies the classpath include/exclude filters to entries found through their descriptors (`META-INF/ejb-jar.xml` and similar).

|`+openejb.deployments.classpath.filter.systemapps+`
|bool
|`+true+`
|Leaves the internal OpenEJB/TomEE jars (`openejb-*`) out of classpath deployment discovery.

|`+openejb.deployments.classpath.include+`
|regex
|`+.*+`
|Regex to filter the scanned classpath: selects which classpath entries are considered for deployment and annotation scanning.

|`+openejb.deployments.classpath.require.descriptor+`
|comma-separated set of EJB, CLIENT
|`+CLIENT+`
|Allows filtering what you want to scan (client modules or EJB modules): module types that are deployed from the classpath only when they contain their descriptor (`ejb-jar.xml` or `application-client.xml`).

|`+openejb.deployments.package.exclude+`
|regex
|`+""+` (nothing)
|Regex to filter scanned packages: class/package names to exclude when classpath modules are scanned for annotations.

|`+openejb.deployments.package.include+`
|regex
|`+.*+`
|Regex to filter scanned packages: class/package names to include when classpath modules are scanned for annotations. When both classpath and package include are left at their defaults, only the packages of the calling classes are included.

|`+openejb.descriptors.output+`
|bool
|`+false+` (`+true+` for an EJB module with validation errors)
|Dump in-memory deployment descriptors (`ejb-jar.xml`, `openejb-jar.xml`, CMP mappings...) to temporary files and log their locations. Can be used to set complete metadata to true and avoid scanning when starting the container, or to check the configuration in use. Can also be set per module in the `openejb-jar.xml` properties.

|`+openejb.descriptors.output.folder+`
|path
|none (system temp dir)
|Where to dump deployment descriptors when `openejb.descriptors.output` is on. The directory is created if needed.

|`+openejb.ear.use-as-webcontext-base+`
|bool
|`+false+`
|For web modules inside an EAR, puts the EAR's module id in front of the context root (`+<ear>/<context-root>+`).

|`+openejb.exclude-include.order+`
|include-exclude or exclude-include
|`+include-exclude+`
|Whether the inclusion or the exclusion wins on conflicts (intersection) when filtering classpath deployments.

|`+openejb.finder.module-scoped+`
|bool
|`+false+`
|Limits the annotation finder results of each module to that module's own classes.

|`+openejb.ignore.directories+`
|comma-separated list
|`+.svn,_svn,cvs,.git,.hg+`
|Names of directories skipped when deployment directories are scanned.

|`+openejb.jarstxt.activated+`
|bool
|`+true+`
|Reads `WEB-INF/jars.txt` (or `META-INF/jars.txt`), which lists extra jars or Maven coordinates to add to the application classloader.

|`+openejb.modulename.useHash+`
|bool
|`+false+`
|Adds a hash after the module name of a web module when the name is generated from the module location. It avoids conflicts between multiple deployments (through ear) of the same webapp. Deactivated by default since names are less nice this way.

|`+openejb.resolver.windows.lowercase-urls+`
|bool
|`+true+`
|On Windows, converts classpath URLs to lower case before they are compared during deployment discovery.

|`+openejb.scan.webapp.container+`
|bool
|`+false+`
|Also adds the container classpath, minus the built-in exclusions, to each webapp's URLs and scanned URLs.

|`+openejb.scan.webapp.container.skip-folder+`
|bool
|`+true+`
|When `openejb.scan.webapp.container` is on, skips directory entries of the container classpath.

|`+openejb.scan.xml.name+`
|string
|`+scan.xml+`
|Name of the descriptor under `META-INF` or `WEB-INF` that lists the classes and packages to scan, which avoids a full annotation scan.

|`+openejb.scanning.xbean.jvm+`
|comma-separated class name prefixes
|`+java.+`
|Class name prefixes that the annotation finder treats as JVM classes and does not scan.

|`+openejb.system.apps+`
|bool
|`+false+`
|Deploys the internal OpenEJB system applications (Deployer, configuration info EJBs). When true, the classpath is not scanned for deployments.

|`+openejb.taglib.scan+`
|bool
|`+true+`
|Scans classloaders and webapps for JSP tag library descriptors (TLDs). Set it to `false` to skip the scan.

|`+openejb.validation.output.level+`
|TERSE, MEDIUM or VERBOSE
|`+MEDIUM+`
|Level of detail of the messages used to report validation errors. The JSR-88 `VmDeploymentManager` reads it as an integer 1-3 (default 3).

|`+openejb.validation.skip+`
|bool
|`+false+`
|Skip the validations done when OpenEJB deploys beans (the `ValidateModules` step).

|`+openejb.vendor.config+`

|`+tomee.deployement-exception-max-size+`

=== Classloading

[options="header",cols="2,1,1,3"]
|===
|Property |Type |Default |Description

|`+<configurer name>.clazz+`
|class name
|none
|When a classloader configurer `clazz` value is not a loadable class, it is read as a comma list of names. The class of each name is read from `+<name>.clazz+` and system properties starting with `<name>` are applied to it (the remaining property name keeps its leading dot, so property injection is unreliable in this mode).

|`+<detection.class.name>.skip+`
|bool
|`+true+`
|JVM system property per optional library, named after a detection class: `org.apache.log4j.Logger.skip`, `org.apache.myfaces.spi.FactoryFinderProvider.skip`, `org.hsqldb.lib.HsqlTimer.skip`, `org.apache.commons.net.pop3.POP3Client.skip`, `org.apache.cxf.jaxws.support.JaxWsImplementorInfo.skip`, `org.apache.activemq.broker.BrokerFactory.skip`. When true and the library is in the container, its classes (and the matching JAX-WS/JMS APIs) come from the container. Set it to `false` to let a webapp bring its own copy.

|`+openejb.api.<class>.validation+`
|bool
|`+true+`
|Per forbidden API class (`jakarta.persistence.Entity`, `jakarta.transaction.Transaction`, `jakarta.jws.WebService`, `jakarta.validation.Validation`, `jakarta.jms.Queue`, `jakarta.enterprise.context.ApplicationScoped`, `jakarta.inject.Inject`, `jakarta.ws.rs.Path`, `jakarta.ejb.EJB`, `jakarta.annotation.PostConstruct`), for example `openejb.api.jakarta.persistence.Entity.validation`. When true, a webapp jar that bundles this class is ignored with a warning. Set it to `false` to keep such jars.

|`+openejb.classloader.configurer.<appId>.clazz+`
|class name or comma list
|none
|Alias of `+tomee.classloader.configurer.<appId>.clazz+`, checked after the `tomee.` keys.

|`+openejb.classloader.configurer.clazz+`
|class name or comma list
|none
|Alias of `tomee.classloader.configurer.clazz`, checked last.

|`+openejb.classloader.delegate-first+`
|bool
|`+true+` unless the container's parent classloader is the system classloader
|Default delegation mode of application classloaders. True means the parent classloader is asked first.

|`+openejb.classloader.filterable-resources+`
|comma-separated resource paths
|`+META-INF/services/jakarta.validation.spi.ValidationProvider+`, `+jakarta.ws.rs.client.ClientBuilder+`, `+jakarta.json.spi.JsonProvider+`, `+javax.cache.spi.CachingProvider+` and `+jakarta.persistence.spi.PersistenceProvider+` services, the JavaMail provider and mailcap files, `+org/slf4j/impl/StaticLoggerBinder.class+`
|Resources for which the webapp classloader drops the container's copy from `getResources()` results when the application provides one too.

|`+openejb.classloader.force-maven+`
|bool
|`+false+`
|Development aid for the TomEE Maven plugin: resources from build output folders (`target/classes`, `target/test-classes`, `build/classes/main` or `test`) are put first in `getResources()` results, ahead of `WEB-INF/classes`.

|`+openejb.classloader.forced-load+`
|comma-separated package/class prefixes
|none
|Class name prefixes that the webapp-first classloader always loads from the application, even when they would normally be container classes. `forced-skip` is checked first.

|`+openejb.classloader.forced-skip+`
|comma-separated package/class prefixes
|none
|Class name prefixes that the webapp-first classloader (and the temp and JPA loaders) always load from the container, never from the application.

|`+openejb.classloader.skip-app-loader-if-possible+`
|bool
|`+true+`
|When an application is deployed from the classpath (embedded, tests) and all its URLs are already on the parent loader, reuses the parent classloader instead of creating an application classloader.

|`+openejb.container.additional.exclude+`
|comma-separated package prefixes
|none
|Extra package prefixes that the container-classes filter (TomEE Embedded, BVal CDI filtering) accepts, meaning they are not treated as container classes. Checked before the built-in lists.

|`+openejb.container.additional.include+`
|comma-separated package prefixes
|none
|Extra package prefixes that the container-classes filter rejects, treating them as container classes to skip during scanning.

|`+openejb.skip.log4j+`
|bool
|`+true+`
|When log4j 1.x is in the container, `org.apache.log4j` classes are treated as container classes, so applications do not load their own copy.

|`+openejb.skip.myfaces+`
|bool
|`+true+`
|When MyFaces is in the container, `org.apache.myfaces` classes are loaded from the container instead of the webapp.

|`+openejb.tempclassloader.skip+`
|comma-separated NONE, ANNOTATIONS, ENUMS, ALL
|`+NONE+`
|Kinds of classes that the temporary (scanning/enhancement) classloader does not define itself and leaves to the parent loader.

|`+tomee.<context>.externalRepositories+`
|comma-separated paths
|unset
|Additional directories or jars added to the classloader of the webapp. `<context>` is the context path without the leading slash, or `ROOT`.

|`+tomee.<warName>.externalRepositories+`

== Service, resource and container properties

These properties are set on a service declaration: in `conf/conf.d/<service>.properties` for server services, or on a `<Resource>`, `<Container>` or `<Service>` in `tomee.xml`, `resources.xml` or `new://` declarations. They can also be overridden with `+<serviceId>.<property>+` system properties.

=== Server service properties

`<service>` is the service name, for example `ejbd`, `ejbds`, `admin`, `httpejbd`, `hsql`, `derbynet`, `activemq`, `multicast`, `multipulse` or `multipoint`. Set them in `+conf/conf.d/<service>.properties+` or as `+<service>.<property>+` system properties.

|string
|none

|`+<service>.timeout+`
|int (ms)
|`+0+` (no socket timeout); ejbd/ejbds request timeout `+14400000+`
|Socket `SO_TIMEOUT` of the service. For ejbd/ejbds it also sets the EJB daemon request timeout (4 hours by default).
