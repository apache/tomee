= REST with Application Composer

This example shows how to test a JAX-RS service with the Application Composer, without building a WAR or starting a full server.
Instead of listing classes, the test builds its deployment programmatically as an `EjbModule`: it declares the REST resource as a singleton EJB and registers a JAX-RS `ExceptionMapper` as a CXF provider through the `openejb-jar` configuration.

== The REST service

`GreetingService` exposes a single `GET` method on `/greeting`. It does not return a value: it always throws an `IllegalArgumentException`.

[source,java]
----
package org.superbiz.composed.rest;

import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;

@Path("/greeting")
public class GreetingService {

    @GET
    public String message() {
        throw new IllegalArgumentException("this exception is handled by an exception mapper");
    }
}
----

== The exception mapper

`IllegalArgumentExceptionMapper` turns an `IllegalArgumentException` into a `200 OK` response whose body is the exception message.

[source,java]
----
package org.superbiz.composed.rest;

import jakarta.ws.rs.core.Response;
import jakarta.ws.rs.ext.ExceptionMapper;
import jakarta.ws.rs.ext.Provider;

@Provider
public class IllegalArgumentExceptionMapper implements ExceptionMapper<java.lang.IllegalArgumentException> {

    @Override
    public Response toResponse(final java.lang.IllegalArgumentException throwable) {
        return Response.ok(throwable.getMessage()).build();
    }
}
----

If the mapper is picked up, a client calling `GET /greeting` receives the exception message as the response body.

== The test

`GreetingServiceTest` runs with the `ApplicationComposer` JUnit runner, which starts an embedded TomEE container for the test class and deploys the module described by the test itself.

[source,java]
----
@RunWith(ApplicationComposer.class)
public class GreetingServiceTest {

    @Configuration
    public Properties configuration() {
        return new Properties() {{
            setProperty(OpenEjbContainer.OPENEJB_EMBEDDED_REMOTABLE, Boolean.TRUE.toString());
        }};
    }

    @Module
    public EjbModule app() {
        final SingletonBean bean = (SingletonBean) new SingletonBean(GreetingService.class).localBean();
        bean.setRestService(true);

        // now create an ejbjar and an openejb-jar to hold the provider config

        final EjbJar ejbJar = new EjbJar();
        ejbJar.addEnterpriseBean(bean);

        final OpenejbJar openejbJar = new OpenejbJar();
        openejbJar.addEjbDeployment(new EjbDeployment(ejbJar.getEnterpriseBeans()[0]));

        final Properties properties = openejbJar.getEjbDeployment().iterator().next().getProperties();
        properties.setProperty("cxf.jaxrs.providers", IllegalArgumentExceptionMapper.class.getName());

        // link all and return this module

        final EjbModule module = new EjbModule(ejbJar);
        module.setOpenejbJar(openejbJar);

        return module;
    }

    @Test
    public void checkProviderIsUsed() throws IOException {
        final String message = IO.slurp(new URL("http://localhost:4204/GreetingServiceTest/greeting/"));
        assertEquals("this exception is handled by an exception mapper", message);
    }
}
----

=== `@RunWith(ApplicationComposer.class)`

The JUnit runner from `org.apache.openejb.junit`. It reads the `@Configuration` and `@Module` methods of the test class, boots the container with that setup and deploys the module before the tests run.

=== `@Configuration`

Returns the `Properties` used to configure the container. Here `OpenEjbContainer.OPENEJB_EMBEDDED_REMOTABLE` is set to `true`, which starts the embedded HTTP layer so the REST service can be reached over HTTP.

=== `@Module`

Describes what gets deployed. Instead of returning a list of classes, this method builds an `EjbModule` by hand, using the `org.apache.openejb.jee` descriptor model:

* `new SingletonBean(GreetingService.class).localBean()` declares `GreetingService` as a singleton EJB with a no-interface view, and `setRestService(true)` exposes it as a JAX-RS resource.
* The bean is added to an `EjbJar`, the programmatic equivalent of `ejb-jar.xml`.
* An `OpenejbJar` (the equivalent of `openejb-jar.xml`) gets an `EjbDeployment` for that bean. The deployment property `cxf.jaxrs.providers` is set to `IllegalArgumentExceptionMapper`, which registers the mapper as a CXF JAX-RS provider for this service.
* Both descriptors are linked in an `EjbModule` via `module.setOpenejbJar(openejbJar)` and returned.

=== What the test checks

`checkProviderIsUsed()` reads `http://localhost:4204/GreetingServiceTest/greeting/` with `IO.slurp` and asserts that the body is `this exception is handled by an exception mapper`.
Because `GreetingService.message()` always throws, this value can only come from `IllegalArgumentExceptionMapper`, so the test proves that the provider configured through `cxf.jaxrs.providers` is used.

== Running

The example is a Maven project. The OpenEJB classes are only needed by the test, so `tomee-webprofile` is declared with `test` scope while `tomee-webprofile-api` is `provided`.

Run the test with:

[source,bash]
----
mvn clean test
----
